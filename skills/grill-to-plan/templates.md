# Templates

Copy, then replace every `<...>`. Keep the headings; agents grep for them.

## `00-overview.md`

```markdown
# <Topic> — overview

Goal: <three lines: what changes, for whom, what stays the same>.

## Working agreement

<Branches per repo. What agents must not touch (generated files, another team's area). Shared
resources and the rule for them ("only one agent at a time may restart the dev server"). The
verification commands every task runs before it is done. Repo-specific conventions live here.>

## Current state (verified <YYYY-MM-DD>)

| Area | Today |
| --- | --- |
| <area> | <what exists, with `path:line`> |

## Decisions (from grill, <YYYY-MM-DD>)

| # | Decision |
| --- | --- |
| D1 | <outcome, phrased as a fact: "Planner = ToolLoopAgent, step cap from env (default 12)"> |

Assumptions (not asked): <each thing you decided alone, one line each>.

## Tasks and order

<ASCII dependency graph>

| File | Task | Est. |
| --- | --- | --- |
| 01-<slug>.md | <one line> | <0.5d> |

## Deferred, do not bury

- **<NN — title>.** Deferred because <prerequisite>. Whoever next touches <area> reads it first.

## Queued after <milestone> (user, <YYYY-MM-DD>)

Run only after <exact gate>.

1. <instruction as given, plus the file it should produce>
```

## `NN-<slug>.md`

```markdown
---
task: NN
title: <title>
phase: A
status: todo
claimed-by:
depends-on: []
commit:
---

# NN — <title>

Decision: D<x>, D<y>. Depends on: <tasks or "nothing">. Blocks: <tasks>.

## Goal

<Two to four lines. What is true when this task is done.>

## Files

- `<path>` — <existing: what changes | new: what it holds>

## Steps

1. <concrete step, with the command or the function to change>
2. …

## Done when

- <a check a stranger can run: command and expected result>

## Out of scope

<what a tempted agent must not do here, and which task does it instead>
```

Blocked-on-a-decision variant (same frontmatter, `status: blocked`):

```markdown
# NN — <title>

**Blocked <YYYY-MM-DD>: needs a product decision on <what>.**

## Observed

<what the user saw, with the ticket or screenshot reference>

## Cause (verified)

<where in the code, `path:line`, and why it behaves this way>

## Options

1. <keep as is> — <consequence>
2. <change> — <exact edits>
3. <middle> — <consequence>

## Done when

Decision recorded here; if 2 or 3, <the edits and the test fixture to update>.
```

## `board.sh`

```sh
#!/bin/sh
# Regenerates BOARD.md from each task file's frontmatter. Run after changing status/claimed-by.
cd "$(dirname "$0")" || exit 1
{
  echo "# <Topic> — board"
  echo
  echo "Generated by board.sh on $(date '+%Y-%m-%d %H:%M'). Edit task frontmatter, not this file."
  echo
  echo "| Task | Phase | Status | Claimed by | Depends on | Commit |"
  echo "|---|---|---|---|---|---|"
  for f in [0-9][0-9]-*.md; do
    [ "$f" = 00-overview.md ] && continue
    awk -v file="$f" '
      /^---$/ { n++; next }
      n == 1 { i = index($0, ":"); k = substr($0, 1, i - 1); v[k] = substr($0, i + 1); sub(/^ +/, "", v[k]) }
      n == 2 { exit }
      END { printf "| %s %s | %s | %s | %s | %s | %s |\n", v["task"], v["title"], v["phase"], v["status"], v["claimed-by"], v["depends-on"], v["commit"] }
    ' "$f"
  done
} > BOARD.md
cat BOARD.md
```

## Handoff prompt for an executing agent

```
Implement task NN of the <topic> plan in <repo path>. Branch <name> is checked out; do not switch
branches.

Read first, in this order:
1. plans/<topic>/NN-<slug>.md — your task, follow it exactly
2. The "Working agreement" and "Current state" sections of plans/<topic>/00-overview.md
3. <repo style rules file>

Hard rules: <the working agreement's must-nots, repeated verbatim>.

When done: set the task's frontmatter to status: done, claimed-by: agent-NN, commit: <sha>; run
plans/<topic>/board.sh.

Final report: every file changed; the exact output of the verification commands; anything you could
not do and why; every behaviour you had to decide that the task file did not specify.
```
